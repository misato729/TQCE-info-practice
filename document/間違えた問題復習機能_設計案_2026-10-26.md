# 「間違えた問題のみを復習」機能 設計案

作成日: 2026-10-26
状態: 実装済み（2026-10-26）
実装との照合更新: 2026-10-28。以下は現行コードの動作を記載し、本番配信・本番動作確認の完了を意味しない。

## 1. 目的

ログインユーザーが、現在も理解できていない問題だけを選んで解き直せるようにする。

既存仕様である次の方針は変更しない。

- 回答履歴は回答1回につき1件保存する
- 受験セッション及び試験結果は管理しない
- 問題演習URLは `/practice/{examNumber}/{questionNumber}` とする
- URLへDB上の問題IDを使用しない
- 回答前の一般向けAPIから正答・解説を返さない
- 現在のログイン状態及びプレミアム会員資格に応じた利用範囲を適用する

## 2. 復習対象の定義

「間違えた問題」は、ユーザー・問題ごとの**最新回答が不正解である問題**とする。

最新回答は `created_at DESC, id DESC` の順で一意に決定する。

| 回答状況 | 復習対象 |
| --- | --- |
| 未回答 | 対象外 |
| 最新回答が不正解 | 対象 |
| 不正解の後に正解 | 対象外 |
| 正解の後に不正解 | 対象 |
| 同じ問題へ複数回不正解 | 1問として対象 |

一度でも間違えた問題を永久に残す方式は採用しない。復習で正解した成果を対象一覧へ反映できないためである。

さらに次の問題だけを対象とする。

- `publication_status = published` の問題
- 現在のユーザーが利用できる模擬試験の問題
- 現在のユーザー本人の回答履歴から導出した問題

無料会員は現在利用可能な模擬試験1〜5、プレミアム会員・管理者・有効な検証用資格を持つユーザーは利用可能な全公開問題を対象とする。利用権限外の問題について、復習対象であることや件数を無料会員へ返さない。

## 3. 画面と導線

### 3.1 トップページ

「問題演習を始める」に3つ目のタブ「間違えた問題」を追加する。

- 未ログイン: ログインが必要なこととログイン導線を表示する
- ログイン済み: タブを開いた時点で復習対象を読み込む。同じ認証状態で取得済みの配列は共有し、毎回のタブ切替ではAPIを再取得しない
- 対象あり: 対象件数と「ランダムに復習を始める」ボタンを表示する
- 対象なし: 「現在、復習する問題はありません」と通常演習への導線を表示する
- 読み込み失敗: 再読み込みボタンを表示する

初期表示では復習対象APIを呼ばない。タブを開いた時に未取得であれば取得し、再読み込みボタンでは強制取得する。タブを開いたままユーザー・認証世代・利用資格が変わった場合も再取得する。

### 3.2 解答履歴ページ

ページ上部へ「間違えた問題をランダムに復習」ボタンを追加する。

- ボタンを押した時に復習対象を読み込む。同じ認証状態の取得済み配列があれば再利用し、未取得又は前回取得に失敗した場合はAPIから取得する
- 対象があれば先頭の問題へ遷移する
- 対象がなければページ内に「現在、復習する問題はありません」と表示する
- 従来の回答単位の履歴一覧及びページ分割は変更しない

### 3.3 問題演習ページ

復習時も既存の問題演習ページを使用する。

```text
/practice/{examNumber}/{questionNumber}?review=incorrect&order=random&seed={seed}
```

復習中は次を表示する。

- 「間違えた問題を復習中」
- 「復習 n / 全m問」の進捗
- 回答後のボタン文言「次の復習問題」

通常の問題取得、回答判定、解説及び根拠資料の表示は変更しない。復習中の回答も従来どおり `answer_histories` へ1件追加する。

1回の復習で使用する対象配列は開始時点のスナップショットとする。

- 復習中に正解しても、その場で配列を詰め直さず次の対象へ進む
- 復習中に再び不正解でも、その周回内ですぐ同じ問題へ戻さない
- 最後の問題へ回答した後に対象APIを再取得する
- 残り0問: 「間違えた問題をすべて正解しました」と表示する
- 残りあり: 「まだn問あります」と「残っている問題をもう一度復習」ボタンを表示する

再読み込み時は最新の回答状態から対象配列を作り直す。表示中の問題が既に対象外で、他に対象がある場合は先頭の対象へ置き換える。対象が0件の場合は解答履歴ページへ戻し、完了状態を表示する。

### 3.4 クエリパラメータ

復習時は次の3項目を使用する。

- `review=incorrect`: 間違えた問題の復習であることを示す
- `order=random`: ランダム順であることを示す
- `seed`: 復習中のランダム順を再現する32ビット非負整数

`review=incorrect` は、通常演習用の次の範囲指定パラメータと併用しない。

- `scope`
- `exams`
- `questions`

`answer_history_id` による過去回答の確認を優先し、履歴確認リンクには `review=incorrect` を付けない。

## 4. 復習順

復習対象は毎回ランダム順で出題する。

1. 復習開始時に復習対象APIから取得した正確な問題ペアを使用する。同じ認証状態の取得済み配列があれば再利用する
2. `createPracticeSeed()` と同じ範囲の乱数シードを生成する
3. シードと各問題の `exam_number`・`question_number` から決定的なランダム順位を計算する
4. ランダム順位で対象問題を並べ、同値の場合は `exam_number`、`question_number` の順で確定する
5. `order=random` と `seed` を各問題のURLへ引き継ぐ

単純な非決定的シャッフルにはしない。同じシードと同じ対象問題であれば同じ順番を再現できるようにする。また、正解した問題が対象から除かれても、残った問題同士の相対順を維持できるよう、配列の件数に依存するFisher–Yates法ではなく、シードと問題ペアから求めた安定したランダム順位を使用する。

新しく復習を開始するたびに新しいシードを生成するため、次の周回では異なる順番になり得る。不正解のまま残った問題を同じ周回内ですぐに再出題することはせず、次の周回で新しいランダム順へ組み込む。

既存の `exams × questions` による条件指定は流用しない。例えば誤答が「模擬試験1・問1」と「模擬試験2・問2」の場合、既存方式では不要な「模擬試験1・問2」「模擬試験2・問1」まで含まれるためである。

## 5. API設計

### 復習対象取得

```text
GET /api/v1/review_questions/incorrect
```

- Better Authのログイン必須
- 本人の回答履歴だけを参照する
- 現在の利用資格を検査する
- ページ分割は行わない
- `HEAD` も既存APIと同様に用意する

レスポンス例:

```json
{
  "data": [
    {
      "question_id": 42,
      "exam_number": 1,
      "question_number": 3
    },
    {
      "question_id": 88,
      "exam_number": 2,
      "question_number": 7
    }
  ],
  "meta": {
    "total_count": 2
  }
}
```

レスポンスへ選択肢、正答、正誤、解説、根拠資料を含めない。`question_id` は問題取得APIで使用する内部識別子であり、画面URLには使用しない。

対象がない場合も `200 OK` とし、`data: []`、`total_count: 0` を返す。未ログイン時は `401 Unauthorized` とする。

## 6. DB設計

復習セッション用テーブル、復習フラグ及び問題ごとの復習状態テーブルは追加しない。`answer_histories` から毎回導出する。

PostgreSQLでは、本人の履歴を `question_id` 単位に分け、`created_at DESC, id DESC` の先頭1件へ絞った後、`is_correct = false` の行を選ぶ。現行実装は `DISTINCT ON (question_id)` を使ったパラメータ化SQLとする。

最新回答取得を安定して効率化するため、Prisma Migrateの `20261026010000_incorrect_review_index` で次の複合インデックスを追加済みである。本番での適用確認とは区別する。

```text
(user_id, question_id, created_at DESC, id DESC)
```

既存の適用済みマイグレーションは変更せず、新規マイグレーションとして追加した。

## 7. フロントエンドの状態管理

復習対象配列は共通composableで管理し、次の情報が変わった場合に破棄する。

- ユーザーID
- `sessionVersion`
- `paid_content_access`

トップページ又は解答履歴ページから開始した場合は、取得済み配列を問題演習ページでも再利用する。直接URLを開いた場合及び再読み込み時は、共有配列が未取得なら取得する。認証情報の変更、明示的な再読み込み及び周回終了時にも再取得する。

ログイン中の回答が成功した場合は、通常演習・復習のどちらでも共有配列を破棄し、次にトップページや履歴ページから開始するときは最新対象を取得する。復習ページ内の周回用スナップショットは保持するため、回答直後に周回の順序や進捗は変えない。

復習対象配列とシードから安定したランダム順を生成し、問題間の遷移では同じ配列とシードを維持する。「残っている問題をもう一度復習」では新しいシードを生成する。

古いユーザー又は古い利用資格の非同期レスポンスは、既存の履歴・お気に入り画面と同様に世代番号で破棄する。

## 8. エラー・境界条件

- セッション切れ: ログインページへ遷移し、復習URLを戻り先として保持する
- 利用資格失効: 対象配列を破棄し、現在利用できる問題だけで再取得する
- 問題が非公開又は削除済み: 対象から除外する
- 問題取得時に権限が変わった場合: 既存問題APIの `401` 又は `403` を優先する
- 別タブで解答状態が変わった場合: 現在の周回は開始時スナップショットを維持し、再読み込み又は次周回で反映する
- 同じ時刻の履歴: `id DESC` を第2ソートキーとして最新を確定する

## 10. 受入条件

1. 最新回答が不正解の問題だけが1問1件で返る
2. `不正解 → 正解` で次回の復習対象から外れる
3. `正解 → 不正解` で復習対象へ戻る
4. 未回答、非公開問題及び別ユーザーの履歴を含めない
5. 無料会員へ利用権限外の問題及びその復習対象件数を返さない
6. プレミアム会員、管理者及び有効な検証用資格では利用可能な全範囲を対象にできる
7. 復習対象の疎な問題ペアだけをランダム順で表示し、直積による余計な問題を含めない
8. 回答前に正答、解説及び根拠資料を返さない
9. 復習中の回答も通常の解答履歴へ保存される
10. 全問終了時に残り0問と残りありを区別できる
11. ログアウト、ユーザー切替及び利用資格変更後に古い復習対象を表示しない
12. デスクトップとスマートフォンで進捗、開始ボタン、完了表示が重ならず、はみ出さない

## 11. テスト方針

- サービス単体: 最新回答判定、同時刻時のID順、本人スコープ、公開状態、利用資格
- API: `200`、空配列、`401`、正答情報を含まないこと
- フロント単体: 疎な問題ペアのランダム化、同一シードでの再現、異なるシードによる順序変更、対象除外後の相対順維持、進捗、再取得、古いレスポンス破棄
- E2E: 開始、複数問遷移、正解後の除外、不正解問題の次周回残留、完了、セッション切れ
- レスポンシブ: デスクトップ及びスマートフォンでトップの3タブ、履歴CTA、復習中表示、完了操作を確認する

## 12. 採用しない案

- 一度でも不正解だった問題を永久に対象へ残す
- 問題又はユーザーへ復習中フラグを保存する
- 復習セッション及び試験結果を新しいDBテーブルで管理する
- 既存の `exams` と `questions` の直積へ誤答問題を変換する
- 初期版で分野絞り込みを追加する
