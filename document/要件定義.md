# 要件定義

## 参考情報
* 高等学校（情報）教員資格認定試験 科目Ⅰの過去問分析記事を参考にする
    * https://qiita.com/misato729/items/c9e35ab0141ab87932dc
* 科目Ⅰは全20問の4択問題で、6割以上が合格ライン
* 出題傾向は以下の大分類で整理する
    * 問1〜問15: 教職教養問題
    * 問16〜問20: 情報科特有問題
* 過去問が少なく傾向が変わる可能性があるため、問題分類や出題範囲はコード上の固定値として後から追加・変更できる設計にする
    * 分野の追加・変更頻度は低い想定のため、管理画面ではなく `utils` フォルダ内の配列で管理する

# サービス方針

* ユーザーがサイトを開いて、すぐに1問ずつ取り組める問題演習を中心機能とする
* 模擬試験1〜5の問題演習はログイン不要とする
* 未ログインユーザーの回答状態は画面内だけで保持し、サーバーには保存しない
* 回答履歴はログインユーザーに限り保存する。お気に入りは有効な有料会員と管理者だけが利用できる
* 問題は試験ナンバーごとに20問を配置し、複数の試験セットを用意できる構成とする
    * 試験セットは問題を整理する単位とし、受験セッションや試験結果は管理しない
* 模擬試験6以降は有料会員向けとし、500円の買い切りで、サービス提供期間中に公開されている全模擬試験を利用できるようにする

# 機能要件

## ログイン機能
* 会員登録ができる
    * ユーザー名、メールアドレス、パスワードを登録する
    * メールアドレスは一意とする
    * パスワードは8文字以上とする
* ログインができる
* ログアウトができる
* 一般画面と管理画面で同一の認証セッションを使用する
    * 一般画面で管理者としてログイン済みの場合、管理画面での再ログインは不要とする
    * 未ログイン状態で管理画面へアクセスした場合は、管理ログイン画面へ遷移する
    * 一般ユーザーのセッションでは管理機能を利用できない
* アカウント削除（物理削除のみ）ができる
    * アカウント削除時、回答履歴・お気に入りも削除する
    * 有料会員がアカウントを削除した場合、有料会員資格も失効し、同じメールアドレスで再登録しても自動復元しない
    * 決済記録は会計、返金及びStripeとの照合に必要な最小限の情報だけをユーザーとの関連を外して保持する

## 問題演習
* トップページから、利用可能な模擬試験を選んで問1から開始できる
    * 模擬試験1〜50を同じ形式で1行10件ずつ並べ、利用権限がない模擬試験6以降にだけ鍵を表示する
    * 各カードには模試番号だけを20pxで中央より1px上に表示する
    * 問題データが未登録の模擬試験も、将来の追加に備えて問題演習ページへの導線だけ先に用意する
* トップページから、対象とする複数の模試番号と複数の問題番号を指定して開始できる
    * 対象模試は模試番号だけ、出題範囲は「問1」〜「問20」を記載したチェックボックスで表示し、それぞれに「全選択」を設ける
    * 「問題番号順に始める」と「ランダムに始める」の2つの開始方法を設ける
    * 問題番号順では、選択した模試番号と問題番号を昇順に組み合わせた先頭から開始する
    * ランダムでは、選択した模試番号と問題番号の全組合せを開始時に並べ替え、その先頭から開始する
    * 選択条件はURLの `exams` と `questions` クエリパラメータで保持する。ランダムの場合は `order=random` と `seed` も保持し、再読み込み後も同じ順序で末尾まで表示する
    * 条件指定によって受験セッションや試験結果は作成しない
* 未ログインユーザー及び無料会員は、公開中の模擬試験1〜5を1問ずつ解くことができる
* 有料会員は、公開中の全模擬試験を1問ずつ解くことができる
* 管理者は、動作確認のため、購入の有無にかかわらず公開中の全模擬試験を利用できる
* 利用権限は画面上の表示制御だけでなく、問題一覧、問題取得、回答、回答履歴及びお気に入りの各APIで検査する
* 問題文と4つの選択肢を表示し、ユーザーが1つを選んで回答できる
* 問題文と選択肢では、令和8年度科目Ⅰの出題形式・難易度を基準として、以下の表示形式を扱えるようにする
    * 通常の文章
    * 枠付きの引用文
    * 過去問形式の穴埋め問題文、空欄を含む抜粋文、空欄ごとの語句を並べた選択肢
    * 表
    * 改行と字下げを保持したプログラム表記
    * 複数のプログラムを比較する表示
* 表はスマートフォンで横スクロールできるようにする
* 複数のプログラムは、表示幅が確保できる場合は横並び、スマートフォンでは縦並びで表示する
* 回答後に以下を表示する
    * 正解または不正解
    * 正答
    * 解答解説
    * 参考にした出題範囲・根拠資料
* 解答確認後、「次の問題」から別の問題へ進むことができる
* 同じ試験ナンバーの問題は、問1から問20までの順序を持つ
* 未ログインユーザーの回答内容および正解・不正解は保存しない
* ログインユーザーが回答した場合は、回答履歴を保存する
* 問題の正答は回答前に表示しない
* 問題・選択肢・解答解説は生成AIで作成する
    * 教育史、特別支援教育、教育心理の選択肢は令和8年度を基準に十分な情報量を持たせ、用語だけで判別できる単純な問題に偏らせない
    * 「適切なもの」を選ぶ問題を中心としつつ、「適切でないもの」を選ぶ問題も一部に含める
    * 「適切なもの」を選ぶ問題では、正答の根拠に加えて、各誤答選択肢が誤りである理由を解説する
    * 「適切でないもの」を選ぶ問題では、誤っている箇所に加えて、その他の選択肢が適切である理由も解説する
    * 法令、学習指導要領、答申などの抜粋穴埋め問題は公式原典と照合し、過去問と同じ導入文の体裁で作成する
    * 根拠資料は1行ごとに `資料名・章節 | https://...` 形式で、公式原典を優先して記録する
* 問題には以下の情報を持たせる
    * 問題文
        * 問題文は、通常文、引用文、穴埋め問題文、空欄を含む抜粋文、表、プログラムなどの表示ブロックを表示順に保持する
    * 試験ナンバー
    * 問番号（1〜20）
    * 4つの選択肢
        * 選択肢は通常文に加え、表形式または空欄ごとの語句を並べた内容を保持できる
    * 正答
    * 解答解説
    * 大分類（教職教養、情報科特有）
    * 小分類
        * 教職教養：1.1 教育基礎総論、1.2 教職概論、1.3 教育制度総論、1.4 教育心理学、1.5 特別支援教育、1.6 教育課程編成論、2.0 道徳教育論、2.1 総合的な学習・探究論、2.2 特別活動論、2.3 教育方法・技術論、2.4 教育におけるICT活用、2.5 生徒指導・進路指導論、2.6 生徒理解と教育相談、2.7 生徒指導・進路指導論
        * 情報科特有：3.1 情報科専門科目、3.2 情報科教育法
    * 参考にした出題範囲・根拠資料
    * 公開状態（下書き、公開、非公開）

## 有料会員・決済

* 本番での動作確認には、購入資格とは独立した期限付きの検証用資格を運用者が手動付与できる（2026年10月19日合意）
    * 付与理由、付与者、期限及び取消日時を記録し、期限は付与から最長7日とする。期限切れ・取消はAPIの各リクエストで判定する
    * 決済・購入済みレコードを作らず、有料機能へのアクセスだけを許可する。一般ユーザーのままとし、管理者権限を付与しない
    * 付与・取消の公開APIや管理画面は設けず、バックエンドの運用コマンドだけを用いる。購入由来の資格、管理者権限、販売開始フラグ及びStripe設定は変更しない
    * 会員情報には購入済みではなく「検証用」と期限を表示する。期限切れ後も履歴・お気に入りは保持し、既存の認可規則で閲覧を制限する

* 有料会員は月額制ではなく、500円（税込）の買い切りとする
    * 自動更新、継続課金、無料期間は設けない
    * 有料会員資格に有効期限は設けず、アカウント削除、全額返金、支払取消し、異議申立てによる取消し又はサービス終了まで有効とする
    * 購入時点で公開済みの模擬試験に加え、購入後に追加される公開中の模擬試験も対象とする
* 決済にはStripe Checkoutのホスト型決済ページを使用する
    * Checkout Sessionは `payment` モードで作成し、初期対応の決済手段はカードとする
    * カード番号などのカード情報は本システムの画面・API・DBで取得または保存しない
    * 決済金額、通貨、商品及び数量はサーバー側の設定から指定し、ブラウザから金額を受け取らない
    * Stripeの支払確定画面でも500円の買い切り、自動更新なし及び返金条件を表示し、利用規約への同意を必須にする
* Checkout Sessionの作成にはログインを必須とする
    * 有料会員及び管理者からの重複購入リクエストは拒否する
    * 同じ無料会員から未完了のCheckout Sessionが複数作成されないよう制御する
* 決済完了後の有料会員資格は、Stripeから届くWebhookをサーバー側で処理して付与する
    * Webhookは未加工のリクエスト本文、`Stripe-Signature` ヘッダー及びWebhook署名シークレットで検証する
    * `checkout.session.completed` の `payment_status = paid` を確認し、サーバー側に保存したユーザー、商品、金額及び通貨と一致する場合だけ資格を有効化する
    * Stripeからの戻りURLやブラウザから送られた「決済完了」の情報だけでは資格を付与しない
    * Stripe Event ID及びCheckout Session IDを一意に保存し、同じWebhookが再送されても決済記録や資格を重複作成しない
* 決済完了画面では、Webhookの反映待ち、反映完了又は決済未完了を表示できるようにする
* 返金は初期実装ではStripe Dashboardから手動で行い、サイト内の返金操作画面は設けない
    * 全額返金が成立した場合は有料会員資格を失効させる
    * 一度成立した返金が非同期で失敗した場合は、Stripeの現在の成立済み返金額へ決済記録を照合する。同じ購入の返金だけを理由に失効した資格で、全額返金も異議申立ても残っていない場合に限り元の資格へ戻す。別の購入・失効理由の資格は変更しない
    * 部分返金には初期対応しない
    * 異議申立てにより資金が取り消された場合は資格を停止し、資金が回復した場合の再開は運営者が確認して行う
* 販売開始前に、料金、提供内容、提供時期、支払方法、返金条件、動作環境、販売事業者情報及び問い合わせ方法を、利用規約と特定商取引法に基づく表記へ反映する
* 販売開始フラグは初期状態を無効とし、Stripeのキー、Webhook、500円のPrice、フロントエンドURL及び販売事業者情報がすべて設定された場合だけCheckout Sessionを作成できる
    * キー・Price・実行モードの不一致、不正な戻り先URLでは販売を無効にする。本番はHTTPSのオリジンと本番モードを使用し、実Stripeでの検証及び運営者の販売開始承認を別途必要とする
* Stripeのシークレットキー、Webhook署名シークレット及びPrice IDは環境変数で管理し、コード、資料、ログへ値を記録しない

### 販売開始前の法務確認資料

* 消費者庁 特定商取引法ガイド「通信販売広告Q&A」: https://www.no-trouble.caa.go.jp/qa/advertising.html

## 回答履歴
* ログインユーザー限定の機能とする
* 問題に回答したとき、以下の情報を保存する
    * 回答した問題
    * 選択した選択肢
    * 正解または不正解
    * 回答日時
* 自分の回答履歴を新しい順に確認できる
* 回答履歴から、過去に間違えた問題とその解説を確認できる
* 有料会員資格を失った後は、模擬試験6以降の履歴本文、正答及び解説を表示しない
* 演習回単位の集計は行わず、回答を1問単位で管理する

## お気に入り
* 有効な有料会員資格を持つユーザー及び管理者限定の機能とし、APIでも一覧取得・登録・解除の権限を確認する
* 問題表示中に、分野表示の左側にある星アイコンからお気に入り登録・解除ができる
* 未登録時は輪郭だけの星、登録時は黄色で塗りつぶした星を表示する
* お気に入り登録した問題を一覧で確認できる
* 有料会員資格がない間はお気に入りを利用できない。既存の登録データは削除せず、資格取得後に利用を再開できる
* 未ログインユーザー又は無料会員が星アイコンを押した場合は、有料会員向けの機能である旨と、有料会員案内への導線をモーダルで表示する。未ログイン時はログインへの導線も表示する
* サイドバーではお気に入りの問題ボタンを薄い黄色の背景と黄色系の枠線で表示する。表示中の問題の枠は別に強調し、両方の状態を識別できるようにする
* 色付け用の問題ID・試験ナンバー・問番号は、既存のログイン及びユーザー情報取得のレスポンスに同梱する。無料会員は空配列とし、お気に入りのDB照会を行わない
* サイドバーの開閉・ページ移動・登録解除後の確認のためにAPI通信を追加しない。同じ画面内では共有状態を即時更新し、別端末の変更は再読み込み又は再ログイン時に同期する

## 試験概要ページ閲覧
* 高等学校（情報）教員資格認定試験についての情報を掲載する。
* 1ページ内に試験概要と過去問ベースの出題範囲の解説を掲載する
* 科目Ⅰの概要として、問題数、選択肢形式、合格ライン、出題範囲を掲載する
* 一般利用者が読む説明とし、公式情報、過去問の出題実績、本サイト独自の予想範囲を区別する。作問の内部ルールは掲載しない
* 情報確認日・対象年度及び公式資料へのリンクを掲載し、科目Ⅰの合格基準を試験全体の最終合格条件と混同させない
* 出題範囲は大分類を「教職教養」「情報科特有」とし、小分類は問題内容に応じて前記の科目名で掲載する
* 問7及び問16〜問18の小分類は問番号だけで固定せず、実際の出題内容に応じて設定する
* 問12は発達障害や通級による指導だけに限定せず、特別支援教育における障害全般を対象とする
* 出題傾向は年度によって変わる可能性があることを明記する

## 管理機能
* 管理者専用のログイン画面を提供する
* 管理APIの利用時は `role = admin` であることを必ず確認する
* 管理者は問題を作成・編集・削除できる
* 管理者は問題の公開状態を変更できる
* 管理画面で公開として保存する場合は、同じ試験ナンバーの問1〜20が各1件登録されていることを必須とし、不足する問番号を表示する。公開状態は問題ごとに設定する
* 管理者は各問題の試験ナンバーと問番号を設定できる
* 初期実装では、決済・有料会員を操作する管理画面は設けず、返金はStripe Dashboard、状態確認はStripe Dashboard及びDBで行う

### 問題データの初期投入と運用切替

* 問題seedは初期投入マスタ用とし、総点検中は承認済みの改稿反映にも使用する。恒久的な編集元にはしない（2026年10月18日合意）
* ユーザーが総点検完了を確認するまでは、問題seed、デプロイ時の自動実行及び管理画面の変更を保護する同期処理を維持する。部分的な改稿完了やリリース成功だけでは切り替えない
* 総点検完了後は本番DBの問題データを正本とし、管理画面で問題を作成・編集する。通常のアプリデプロイと問題更新を分離し、問題seedとその自動同期を廃止する
* 切替前に最終承認内容の本番反映と、問題・選択肢・公開状態及び関連データのバックアップ・書き出し・復元手順を確認する。これらの整備・検証は今後の切替作業で行い、対応済みとはみなさない
* 切替後も管理者認可、4択・正答1件、公開時の検査及び内容変更時の回答履歴削除を維持する。通常の問題編集で問題IDとお気に入りを保持し、問題seedの廃止を理由に本番の問題を削除しない
* 品質検査は原典fixtureと承認記録を保持し、実行用seedに依存しない形で継続する。同期記録への管理APIの依存と初期DBへの自動投入経路を整理してから切り替える。具体的な実装は総点検完了後の別作業とする

# 非機能要件
* パスワードはハッシュ化して保存
* 認証方式は Rails API と Nuxt の構成に合わせて決定する
    * Cookie ベース認証またはトークンベース認証を検討する
    * 本番環境では HTTPS を前提とする
* フロントエンドとバックエンドのドメインが分かれるため、CORS 設定を行う
* 公開前の一般利用者の閲覧制限はNetlifyのPrivate設定で行い、フロントエンドのBasic認証は設けない（2026年10月19日合意）。会員ログイン、管理者権限及び有料コンテンツの認可は維持する。ローカルのフロントエンドにもBasic認証を要求しない
* Basic認証廃止版の配信前に本番・プレビュー・各デプロイURLのPrivate適用を確認する。旧Vercel等には保護なしの版を自動配信せず、最後の保護済み成功デプロイを切戻し用に保持する
