# 本番検証用アカウント

対象: [Issue #3](https://github.com/misato729/TQCE-info-practice/issues/3)

## 目的と承認範囲

2026年10月19日、ユーザーから本番の有料会員・管理者アカウントの作成と動作確認を依頼された。決済レコードが必須という既存構成を確認し、偽の支払済み記録を作らないため、購入とは独立した検証用の手動付与に対応するDB・処理・資料の変更及び本番反映の承認を得た。

- 一般の検証用アカウント1件と管理者1件を新規作成する。既存ユーザーを無断で昇格させない。
- 一般アカウントの有料機能利用には `verification_access_grants` を使用し、購入由来の `memberships` と `payments` は作らない。
- 付与理由・付与者・期限を記録する。期限は最長7日で、未取消かつ期限内だけ有効。
- 管理者は既存の `role = admin` を使う。一般の検証用資格で管理権限は得られない。
- 資格の付与・取消用HTTP APIは設けず、DBへ接続できる運用者のコマンドだけを使用する。
- NetlifyのPrivate、販売開始フラグ、Stripe設定、問題・選択肢・公開状態は変更しない。
- 本番へのアカウント作成・権限付与と、パスワードの生成・保管方法は対象を示して確認する。認証情報をコード・資料・ログに記載しない。

これは有料機能へのアクセス確認であり、Stripeの購入・Webhook・返金の実決済試験を完了したことにはならない。

## 付与と取消

READMEの「本番確認用の期限付き資格」を参照する。既存の資格を上書きしない。重複付与はエラーとなる。取消は `revoked_at` を記録し、繰り返しても取消日時を変更しない。取消・期限切れで履歴やお気に入りは削除しない。

検証終了後の管理者アカウントの保持・一般会員への変更・削除はユーザーと決める。アカウントの削除は関連履歴も失うため、作成依頼を削除の承認とは扱わない。検証用の一般資格は指定した期限で自動失効する。
